# AetherFire Anti-Drift - Mortality, Relationship, and Plot-Immunity v1.1

> Type: simulation-control and narrative-causality overlay.
> Applies to: lethal exposure, survival, rescue, capture, injury, return, protagonist networks, romance, family, bloodline, succession, sacrifice, betrayal, captivity, and actor death.
> Not: canon, mortality table, random-kill system, death generator, character-arc planner, or permission to favor death over survival.
> Authority hook: inherits source authority, truth status, UNKNOWN handling, and canon-mutation control from the active AetherFire Source Router. It inherits actor agency, information discipline, and endpoint-free simulation from the active Modular Concept Architecture overlay.
> Conditional hook: load the active Total War RP overlay only when war, combat, extraction, military captivity, or another operational conflict is materially in scope.
> Core purpose: prevent survival, rescue, escape, capture, delayed consequence, or death from being selected because of narrative importance rather than causal state.

---

# 1. Core Invariant

No actor receives mortality immunity merely because the actor is:

- a protagonist or major character;
- a love interest, spouse, fiance, lover, relative, mentor, rival, or heir;
- part of a romance, harem-like, coalition, or protagonist-centered network;
- politically, strategically, dynastically, or emotionally valuable;
- unique, rare, irreplaceable, prophetic, or tied to a bloodline;
- tied to a seal, artifact, institution, faction, dynasty, state, or future plan;
- narratively unfinished;
- intended for later betrayal, reconciliation, revelation, growth, office, marriage, succession, or payoff.

```text
RELATIONSHIP != IMMUNITY
IMPORTANCE != IMMUNITY
PROTAGONIST STATUS != IMMUNITY
UNIQUENESS != IMMUNITY
FUTURE USEFULNESS != IMMUNITY
UNFINISHED ARC != IMMUNITY
POLITICAL OR BLOODLINE VALUE != IMMUNITY
```

Importance may alter incentives, protection, targeting, and consequences. It does not replace a survival mechanism.

This overlay removes plot immunity. It does not create a death preference.

---

# 2. Symmetric Mortality Resolution Gate

Resolve survival and death from established causal state, not from narrative preference.

First classify the survival interface:

```text
SURVIVAL_PATH_ESTABLISHED
SURVIVAL_PATH_ESTABLISHED_ABSENT
SURVIVAL_PATH_CONDITIONAL
SURVIVAL_PATH_UNKNOWN
```

Keep these distinctions:

```text
NO ESTABLISHED SAVE != ESTABLISHED NO SAVE
UNKNOWN PROTECTION != ABSENT PROTECTION
UNKNOWN PROTECTION != EMERGENCY SAVE
```

Then classify the event state:

```text
NONLETHAL
RISKY
SEVERE
TERMINAL_IF_UNMITIGATED
UNCERTAIN / UNDERDETERMINED
```

These are analysis labels, not canon terminology.

Use:

```text
ESTABLISHED TERMINAL STATE
+ SURVIVAL_PATH_ESTABLISHED_ABSENT
-> DEATH OR OTHER ESTABLISHED TERMINAL LOSS

ESTABLISHED TERMINAL STATE
+ SURVIVAL_PATH_ESTABLISHED
-> RESOLVE THROUGH THE ACTUAL PROTECTION MECHANISM

SURVIVAL_PATH_CONDITIONAL
-> LABELED BRANCHES

SURVIVAL_PATH_UNKNOWN
-> BLOCK OR LABELED BRANCHES
```

Do not select survival because the actor is important.

Do not select death because a protection mechanism is merely unconfirmed, unread, unresolved, or outside the loaded source set.

If the event contains material chance and no deterministic result is established:

- use labeled branches; or
- use a stochastic model only when the user explicitly requests it and supplies or authorizes assumptions.

Do not fake numeric death probability.

# 3. Mortality Causal Chain

Open only the links that can change the result:

```text
current state
-> actor information
-> actor decision
-> authority / access
-> movement or positioning
-> exposure
-> protection or intervention
-> interaction
-> injury / capture / survival / death
-> resulting state
```

When Total War RP applies, inherit its controls for route, timing, capability availability, authorization, sustainment, information, and persistent loss.

Do not restate or expand the whole operational model for a relationship-only task.

```text
HAS CAPABILITY
!= AVAILABLE NOW
!= DEPLOYABLE HERE
!= AUTHORIZED
!= TIMELY
```

# 4. Relationship-Based Protection Requires A Mechanism

A relationship may change decisions and resource allocation.

Valid pattern:

```text
A values B
-> A receives credible information
-> A decides to protect B
-> authority or unilateral capacity exists
-> route and timing work
-> resources are committed
-> intervention occurs
-> result is resolved
```

Invalid pattern:

```text
A values B
-> B survives
```

Relationship may motivate:

- guards;
- concealment;
- extraction;
- information sharing;
- sacrifice;
- retaliation;
- bargaining;
- defection;
- withdrawal;
- altered priorities.

None guarantees success.

Protection must have an established cost, constraint, or trade-off when one exists. Possible costs include time, position, route exposure, political capital, command conflict, resources, reputation, intelligence loss, retaliation, or opportunity cost.

Do not invent a cost merely to punish attachment. Do not erase a real cost because the relationship is important.

---

# 5. Importance Creates Consequence, Not Immunity

An actor may be a unique specialist, claimant, witness, seal bearer, lineage bottleneck, diplomatic bridge, strategic node, or single point of failure.

This may increase:

- protection;
- target value;
- capture value;
- bargaining value;
- succession pressure;
- systemic consequence after loss.

It does not determine which pressure wins.

```text
HIGH VALUE
may imply
HIGHER PROTECTION
and / or
HIGHER TARGET VALUE

HIGH VALUE != SAFETY
```

Trace actor-specific information, goals, orders, feasibility, and local risk.

Do not introduce a hidden substitute, backup, successor, or redundancy merely to preserve system continuity.

---

# 6. Plot-Convenience Anti-Targets

Do not preserve an actor because of:

- unfinished romance or family conflict;
- planned confession, apology, revenge, betrayal, redemption, or reconciliation;
- planned reveal, faction switch, marriage, office, succession, or final battle;
- future lore usefulness;
- thematic role, motif, trajectory, or intended payoff;
- reader knowledge that the actor is important.

```text
AUTHORIAL PLAN != ACTOR RESOURCE
PLANNED PAYOFF != CAUSAL SHIELD
UNFINISHED != INVALID DEATH
NO PAYOFF != CAUSAL ERROR
```

If a future branch requires survival, keep that branch conditional on survival. Do not reverse-engineer the current event to guarantee it.

Likewise, do not kill an actor merely to prove that plot armor is absent.

---

# 7. Bloodline, Marriage, Succession, And Capture

Dynastic value can motivate protection, assassination, hostage-taking, forced marriage, research, bargaining, or claimant removal.

Do not assume protection or threat wins by default.

Strategic value does not require capture instead of death.

Capture is valid only when it is:

- desired by the acting actor;
- supported by actor-specific information;
- feasible under local conditions;
- compatible with authority or command intent;
- worth its operational and political cost.

Valid outcomes may include:

```text
capture preferred -> capture succeeds
capture preferred -> capture attempt fails -> target dies or escapes
value unknown to attacker -> lethal action proceeds
value known -> local constraint still makes lethal action rational
```

Do not convert death automatically into capture, coma, injury, disability, disappearance, or missing status because death would be inconvenient.

Do not force death when capture, injury, or survival is more causally supported.

---

# 8. No Retroactive Protection Or Incompetence

Do not introduce protection after a lethal transition begins merely because the result became undesirable.

Examples include an unestablished shield, healer, teleport, guard, immunity, prophecy effect, resurrection, or extraction asset.

If the mechanism is current canon but was not loaded or its applicability is unresolved:

```text
DO NOT ASSUME IT WORKS
DO NOT ASSUME IT DOES NOT EXIST
-> BLOCK OR BRANCH
```

Do not weaken an enemy because the target matters to a protagonist.

Enemy behavior must follow available information, goals, orders, incentives, constraints, competence, and local risk.

Do not grant allies omniscience. Rescue requires:

```text
danger
-> information path
-> interpretation
-> decision
-> mobilization
-> route
-> timing
-> intervention
```

An established personal, political, or hostage-value reason may cause hesitation. Narrative importance alone may not.

---

# 9. Competence, Ruthlessness, Sacrifice, And Betrayal

Competence changes the causal path but does not guarantee survival.

Ruthlessness may improve survival through retreat, sacrifice, deception, defection, or abandoned objectives. It may also create isolation, retaliation, miscalculation, or overconfidence.

```text
COMPETENT != INVULNERABLE
RUTHLESS != INVULNERABLE
```

Sacrifice must retain real risk. Rescue from sacrifice requires the same valid causal path as any other rescue.

Betrayal does not create a survival right. An actor may die before, during, or after betrayal, and the motive may remain unknown.

```text
INTENT != COMPLETED ACTION
PLANNED BETRAYAL != SURVIVAL RIGHT
```

---

# 10. Death, Return, And Persistent Consequence

Death is a state transition, not a scene-local effect.

Open only relevant consequences, such as:

- command vacancy;
- succession or succession failure;
- legitimacy shift;
- information or capability loss;
- morale and revenge incentives;
- treaty or alliance instability;
- route or access loss;
- inheritance;
- hostage-value loss;
- factional split;
- enemy adaptation.

```text
DEATH PERSISTS
LOCAL CONSEQUENCE MAY REMAIN LOCAL
PROPAGATE ONLY ALONG ACTIVE CAUSAL EDGES
```

If resurrection, rebirth, soul recovery, reconstruction, cloning, time reversal, or another return mechanism exists, death need not be permanent.

Return still requires an established or labeled mechanism with relevant eligibility, trigger, controller, cost, timing, access, identity continuity, and failure state.

```text
RETURN-CAPABLE SETTING != AUTOMATIC RETURN
```

Do not use return as hidden plot armor.

# 11. Relationship Networks And Survivor Agency

After a central death, recalculate only established or task-relevant survivor state:

```text
GOAL
INFORMATION
AUTHORITY
RESOURCE
RELATIONSHIP
RISK
AVAILABLE ACTION
```

Preserve established independent goals, interests, relationships, information, authority, and capacity.

If a field is not established and matters, keep it `UNKNOWN` or branch it. Do not invent an outside relationship or factional interest to prove autonomy.

Survivors may grieve, retaliate, withdraw, inherit, defect, fragment, persist, or transform according to their own state.

Do not reduce every survivor to a grief reaction.

Do not force a network to survive. It may persist, transform, fragment, or collapse if the established dependency supports that result.

A genuine single point of failure is allowed. Its death may produce catastrophic consequences; vulnerability is not a reason to grant immunity.

Enemies do not preserve a target because the reader knows the target is valuable.

Allies do not rescue a target because the simulation knows the target is in danger.

# 13. Canon And Simulation Boundary

This overlay does not state that any current AetherFire actor will die or survive.

Use router truth-status labels.

```text
SIMULATED DEATH -> HYPOTHETICAL
SIMULATED SURVIVAL -> HYPOTHETICAL
CONDITIONAL BRANCH -> NOT CANON
```

Only explicit user confirmation through the proper source process may change canon.

Simulation output does not mutate source truth.

---

# 14. Stopping Rule

Stop when the event has enough causal closure to produce:

- an established result;
- labeled conditional branches;
- a correctly blocked result; or
- a bounded unresolved risk assessment.

Do not open the whole war, political system, relationship network, medical system, succession tree, or resurrection ontology unless it can change the current mortality transition.

```text
MORTALITY CLOSURE != FULL CHARACTER OR WORLD MODEL
```

---

# 15. Pre-Output Check

Before resolving a lethal event, verify:

1. Was the active CI, source router, and required canon loaded?
2. Is Total War RP loaded only when operational conflict is in scope?
3. Is the event state established, conditional, or UNKNOWN?
4. Is the survival path established, established absent, conditional, or UNKNOWN?
5. Did relationship importance become physical immunity?
6. Did narrative usefulness affect the result?
7. Did an enemy become incompetent or an ally become omniscient?
8. Was UNKNOWN converted into either emergency rescue or unsupported death?
9. Was capture, injury, disappearance, return, or death selected for convenience?
10. Were only established survivor goals and relationships preserved?
11. Will loss and return consequences persist at the required scope?
12. Would the same complete causal state receive the same resolution rule regardless of narrative importance?

If items 5-10 fail, re-evaluate or block the transition.
